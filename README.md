## Как тестировать компилятор С

Тестирование компилятора C — это комплексный процесс, включающий проверку лексического, синтаксического и семантического анализа, оптимизации и генерации кода. Главная задача — убедиться, что компилятор компилирует правильный код в корректный машинный код для целевой архитектуры. 

1. Метод дифференциального тестирования (Differential Testing)
Это золотой стандарт поиска скрытых логических ошибок (ошибок генерации кода).
Суть: Берется генератор случайного кода, который создает корректные программы на C.
Процесс: Сгенерированный код компилируется несколькими компиляторами (например, вашими и GCC/Clang) с различными уровнями оптимизации (-O0, -O1, -O2, -O3).
Сравнение: Полученные исполняемые файлы запускаются, а их результаты (вывод в консоль или контрольные суммы глобальных переменных) сравниваются между собой.
Инструменты: Самый известный инструмент — Csmith. Он гарантирует, что созданные программы не содержат неопределенного поведения. 

2. Использование готовых тестовых наборов (Test Suites)
Вам не обязательно писать все тесты с нуля. Существуют огромные базы, которые проверяют соответствие стандартам языка:
GCC и LLVM Test Suites: Включают тысячи тестов на различные конструкции языка Си.
Дефектные тесты (Torture Tests): Наборы из репозиториев GCC, созданные специально для того, чтобы «ломать» компиляторы краевыми случаями (сложные циклы, длинные выражения, вложенные структуры).

3. Фаззинг (Fuzzing) компилятора
Фаззинг направлен на то, чтобы заставить компилятор аварийно завершить работу (упасть), зависнуть или выдать ложную ошибку, обрабатывая некорректный код. 

 - Генераторы случайных мутаций (например, C-Reduce для минимизации тестов) позволяют быстро находить ошибки выделения памяти и утечки в самом компиляторе.

4. Юнит-тестирование отдельных фаз
Классический компилятор состоит из нескольких этапов:
Лексический анализ: Тестируется лексерами (например, Flex), проверяется корректность токенов.
Синтаксический анализ: Проверяется деревом разбора (например, сгенерированным Bison/Yacc), корректно ли строятся AST-деревья.
Семантический анализ: Тестируется проверка типов и области видимости.
Генератор кода (Backend): Проверяется ассемблерный код или IR (промежуточное представление) на соответствие логике. 

5. Пошаговая отладка и проверка (Sanitizers)
Для того чтобы понять, где компилятор допускает ошибку, можно использовать санитайзеры во время сборки самого компилятора:
Запустите ваш компилятор под управлением AddressSanitizer ( -fsnitize=address ), чтобы отловить ошибки работы с памятью (например, выход за границы массива во время оптимизации).
Используйте Valgrind для тех же целей.
